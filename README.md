# Лабораторная работа №1 — вариант 9: конус

Приложение C++20 с Vulkan, GLFW и ImGui для оценки **4**: конус с закрытым основанием и первые пять дополнительных пунктов задания — выбор проекции, преобразования, движение и вращение по сложной траектории, выбор цвета через ImGui и процедурные цвета вершин, умножаемые на выбранный цвет. Используется один объект; несколько объектов относятся к заданию на 5.

Основа — [стартовый проект преподавателя](https://github.com/vladeemerr/vulkan-starter-app). Его `LICENSE` и `NOTICE` сохранены. Исходные материалы в родительской папке проекта не изменяются.

## Сборка и запуск

Рабочая папка — `lab1` рядом с материалами лабораторной. Для Windows x64 используются локальные инструменты:

| Инструмент | Версия | Папка внутри `lab1` |
| --- | --- | --- |
| LLVM-MinGW, UCRT x64 | 20260922 | `.tools/llvm-mingw-20260922-ucrt-x86_64` |
| CMake | 4.4.4 | `.tools/cmake-4.4.4-windows-x86_64` |
| Ninja | 1.13.2 | `.tools/ninja` |
| Vulkan SDK | 1.4.321.1 | `.tools/VulkanSDK/1.4.321.1` |

Источники загрузок и контрольные суммы фиксируются в `tools.lock.json`. Зависимости C++ закреплены по ревизиям в `CMakeLists.txt`: GLFW, vk-bootstrap, Vulkan Memory Allocator, ImGui и GLM. Они собираются тем же компилятором, что и приложение.

Из командной строки в папке `lab1` выполните:

```bat
build.cmd
run.cmd
```

Из PowerShell используйте `./build.cmd` и `./run.cmd`. Можно запускать CMD-файлы двойным щелчком; при ошибке удобнее открыть терминал, чтобы сообщение осталось видно.

`build.cmd` настраивает проект и собирает приложение и шейдеры. При первой настройке нужен доступ к GitHub для загрузки зависимостей в `build/_deps`; повторная сборка использует сохранённые исходники. Файлы GLSL автоматически компилируются в `build/shaders/*.spv`. Результат сборки — `build/lab1.exe`.

После первой успешной сборки можно выполнить `build.cmd --offline`: CMake будет использовать уже загруженные зависимости без обращения к сети.

Оба CMD-файла сами переходят в свою папку и используют кавычки в путях. На Windows приложение находит шейдеры относительно EXE через Unicode API, поэтому загрузка шейдеров не зависит от текущей папки терминала. При отсутствии шейдера выводится сообщение с его путём и советом запустить `build.cmd`; приложение завершается с ненулевым кодом. Путь к слоям Vulkan задан относительно папки проекта, чтобы установленный загрузчик Vulkan корректно работал с кириллицей в имени родительской папки.

Переменные `PATH`, `VULKAN_SDK` и `VK_LAYER_PATH` задаются только внутри запускаемых процессов благодаря `setlocal`. Глобальные переменные среды, драйвер и параметры защиты Windows не изменяются. Для работы требуется установленный драйвер видеокарты с Vulkan; SDK содержит средства разработки и проверки, но не заменяет драйвер.

SDK размещён локально официальным установщиком LunarG в режиме `copy_only=1`; подпись установщика проверена. Для повторной установки: установщик этой версии не принимает кириллицу в пути, поэтому папка `lab1` временно отображалась как диск `V:` через `subst`. После копирования отображение удалено; сами файлы находятся в `.tools/VulkanSDK/1.4.321.1`. Значения пользовательских и системных `PATH` и `VULKAN_SDK` до и после установки совпали. При повторной установке используйте официальные источники из `tools.lock.json`, проверяйте опубликованные суммы и подпись, сохраняйте не менее 3 ГБ свободного места на C:.

## Управление

Окно открывается размером 1280 × 720. Панель ImGui расположена слева; подписи на английском:

| Элемент | Значение |
| --- | --- |
| `Projection` | Выбор проекции |
| `Perspective` | Перспективная: удалённые части выглядят меньше |
| `Orthographic` | Ортографическая: размер не зависит от расстояния |
| `Position` | Положение по X, Y, Z, от −3 до 3; перетаскивайте значения мышью |
| `Rotation` | Поворот вокруг X, Y, Z в градусах, от −180° до 180° |
| `Scale` | Масштаб по каждой оси, от 0,1 до 3 |
| `Color` | Цвет-множитель RGB; нажмите цветной квадрат для палитры. Белый сохраняет исходные цвета вершин, чёрный делает конус чёрным |
| `Play` / `Pause` | Начать или приостановить движение и вращение. Продолжение сохраняет текущую фазу |
| `Reset motion` | Остановить анимацию и вернуть её в начало, сохранив ручные преобразования, цвет, скорость и размеры траектории |
| `Speed` | Скорость анимации от 0,1× до 3×; при 1× полный цикл занимает около 6,28 с |
| `Path radius` | Размах траектории по X от центра в каждую сторону, от 0 до 1,5 |
| `Vertical range` | Размах по Y от центра в каждую сторону, от 0 до 1 |
| `Depth range` | Размах по Z от центра в каждую сторону, от 0 до 1 |
| `Reset all` | Сброс проекции, преобразований, цвета и настроек анимации; движение остановлено в начале траектории |

Камера неподвижна и смотрит на начало координат. Чтобы рассмотреть основание, поверните конус по X примерно на 160°. При изменении размера окна соотношение сторон проекции обновляется. Закрытие — обычной кнопкой окна.

При запуске анимация стоит на паузе: нажмите `Play`. Ручные `Position` и `Rotation` задают базовые положение и поворот; анимация добавляется к ним. Цвет и размеры траектории можно менять во время движения и на паузе.

## Как устроено решение

**Геометрия.** Ось конуса — Y, радиус основания — 1, высота — 2. Вершина находится в `(0, 1, 0)`, центр основания — в `(0, −1, 0)`. Для 64 точек окружности используются координаты `(cos(a), −1, sin(a))`, где `a = 2πi / 64`. Каждая пара соседних точек образует один треугольник с вершиной конуса и один с центром основания. Итого 128 треугольников, 384 индекса и 66 вершин. Боковая поверхность и основание используют общие вершины обода.

**Цвет.** При создании геометрии локальные координаты переводятся в RGB: `R = (x + 1) / 2`, `G = (y + 1) / 2`, `B = (z + 1) / 2`. Для данного конуса координаты лежат в диапазоне `[−1, 1]`, поэтому компоненты цвета находятся в `[0, 1]`. Цвет вершины хранится в вершинном буфере. Вершинный шейдер покомпонентно умножает его на цвет из `ImGui::ColorEdit3`, переданный через uniform. Цвета интерполируются внутри треугольников и перемещаются вместе с объектом.

**Отрисовка.** Вершины содержат положение и цвет; индексы задают треугольники с обходом против часовой стрелки при взгляде снаружи. Буферы вершин и индексов передаются в Vulkan, отрисовка выполняется через `vkCmdDrawIndexed`. Проверка глубины обеспечивает правильное перекрытие поверхностей, а отсечение обратных граней скрывает внутренние стороны. Вершинный шейдер преобразует положение, фрагментный выводит интерполированный цвет. Освещение и текстуры здесь не используются.

**Матрицы.** Для столбца координат вершины используется преобразование:

```text
clip_position = P * V * T * Rx * Ry * Rz * S * position
```

`S` — масштаб, `Rx/Ry/Rz` — повороты, `T` — перенос, `V` — вид из камеры, `P` — проекция. Операции действуют на вершину справа налево. В GLSL передаётся уже вычисленное произведение MVP. Проекция использует диапазон глубины Vulkan `[0, 1]`; знак Y меняется для системы координат кадрового буфера Vulkan.

**Анимация.** Фаза `t` увеличивается на прошедшее время кадра, умноженное на `Speed`. Положение на пространственной «восьмёрке» и дополнительные углы в градусах:

```text
offset = (radius * sin(t), height * sin(2t), depth * sin(3t))
rotation = (25 * sin(2t), t * 180 / pi, 15 * sin(3t))
```

В плоскости XY получается восьмёрка, а колебание по Z делает траекторию пространственной. Фаза циклически возвращается к началу после `2π`. На паузе она не меняется; изменение скорости влияет только на дальнейшее движение. После долгой задержки, например сворачивания окна, шаг ограничен 0,1 с, чтобы конус не перескакивал далеко по траектории.

**Uniform.** Один uniform buffer хранит матрицу `mat4 mvp` и множитель цвета `vec4 tint`; один набор дескрипторов связывает его с `set = 0, binding = 0` вершинного шейдера. GLSL-блок объявлен с `layout(std140)`. В C++ структура `SceneUniform` имеет `alignas(16)`: размер 80 байт, смещение матрицы 0, шаг её столбца 16 байт, смещение цвета 64. Эти условия проверяются `static_assert`. Четвёртая компонента цвета равна 1; для RGB используется `tint.rgb`. Матрица и `vec4` естественно удовлетворяют выравниванию 16 байт, ручное заполнение не требуется. Это следует правилам из `Instrument uniform.txt`.

Перед обновлением uniform программа ждёт завершения предыдущего кадра через fence. После записи вызывает `vmaFlushAllocation`, чтобы данные были видны GPU и при некогерентной памяти. Одновременно обрабатывается один кадр, поэтому одного uniform buffer достаточно.

**Разделение кода.** `source/cone_mesh.hpp` строит геометрию и цвета вершин; `source/animation.hpp` вычисляет движение. В `source/application.cpp` находятся настройки, функция `makeMvp`, интерфейс и четыре функции жизненного цикла: `initialize`, `update`, `render`, `shutdown`. Они вызывают подготовку ресурсов, обновление анимации, отрисовку и освобождение ресурсов.

`source/graphics.cpp` содержит работу с ресурсами конуса: загрузку шейдеров, буферы, uniform, дескрипторы, графический конвейер и команды Vulkan. Из приложения используются три функции: `initializeCone`, `renderCone`, `shutdownCone`. Обновление uniform выполняется внутри `renderCone` после ожидания предыдущего кадра. `source/graphics_internal.cpp` — основа стартового проекта: инициализация Vulkan, ресурсы окна, синхронизация и вывод кадров. `source/main.cpp` содержит запуск, основной цикл и обработку ошибок.

## Как читать код перед защитой

Начните с `source/cone_mesh.hpp`: координаты вершин, цвета и два треугольника на каждый сегмент. Затем разберите `source/animation.hpp`: изменение фазы, смещение и углы поворота. В этих файлах вычисления записаны отдельными шагами с промежуточными переменными.

В `source/application.cpp` сначала прочитайте `Controls`, затем `makeMvp` и `update`. Это настройки объекта, матрицы и интерфейс. В `shaders/cone.vert` и `shaders/cone.frag` видно, как GPU использует матрицу и цвет.

Для работы с Vulkan нужно понимать назначение буферов, дескрипторов, конвейера, проверки глубины и ожидания кадра. Имена всех функций заучивать не требуется: подробные вызовы можно смотреть в `source/graphics.cpp` по мере разбора этих понятий.

Программа запрашивает Vulkan validation, если слои доступны. Сообщения видны в консоли. Это диагностика работы Vulkan при обычном запуске.
